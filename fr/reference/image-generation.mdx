---
title: Génération d'images
description: Génération d'images asynchrone ou avec compatibilité d'attente synchrone.
---

Utilisez `/v1/images/generations` pour la génération d'images en production.

```bash
curl https://apiany.ai/v1/images/generations \
  -H "Authorization: Bearer $APIANY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "nano-banana",
    "prompt": "A bright API dashboard rendered as a product hero image",
    "size": "1k"
  }'
```

La réponse renvoie une tâche :

```json
{
  "task_id": "task_123",
  "status": "processing",
  "poll_url": "/v1/tasks/task_123"
}
```

## Variante synchrone

`/v1/images/generations/sync` crée une tâche et attend jusqu'au temps d'attente maximum configuré.

Utilisez-la pour la compatibilité et les démos. Utilisez l'endpoint asynchrone pour les charges de travail en production.

## Édition d'images

`/v1/images/edits` prend en charge les workflows d'édition d'images de style OpenAI lorsque le modèle sélectionné prend en charge les images de référence.

## Qualité et routage de GPT Image 2.5

`gpt-image-2.5` est un alias fixe de Flare ; utilisez `gpt-image-2.5-sunburst` pour l’édition précise. `quality` (`auto/low/medium/high/xhigh/max`) et `resolution` (`1K/2K/4K`) sont indépendants. Les pixels explicites doivent correspondre à la résolution, et APIAny choisit uniquement les routes compatibles par coût sans supprimer de champs.

```json
{"model":"gpt-image-2.5-flare","prompt":"Visuel principal de produit","size":"16:9","resolution":"2K","quality":"high","n":1}
```

L’édition accepte jusqu’à 16 références et un masque facultatif.

```json
{"model":"gpt-image-2.5-sunburst","prompt":"Remplacer uniquement le fond","image_urls":["https://example.com/product.png"],"mask_url":"https://example.com/mask.png","resolution":"2K","quality":"xhigh"}
```

## GPT Image 2.6

`gpt-image-2.6` utilise les endpoints d’image existants pour PNG et GIF animé ; aucune API GIF distincte n’est nécessaire. Chaque requête réussie coûte **30 crédits** et renvoie un résultat. Vérifiez la disponibilité dans `GET /v1/models` avant l’appel.

Utilisez `output_format: "png"` (par défaut) ou `"gif"`, `quality: "auto"`, `resolution: "1K"` et `n: 1`. `size` accepte `auto`, `1:1`, `3:2`, `2:3`, `1024x1024`, `1536x1024` ou `1024x1536`. Une seule référence est acceptée. Les alias et `model_params` ont les mêmes limites ; les valeurs contradictoires renvoient HTTP `400`.

SVG, JPEG, WebP, 2K/4K, les masques, la compression, `frame_count` et `frame_duration_ms` ne sont pas pris en charge. Les dimensions, le nombre d’images et les intervalles du GIF ne sont pas configurables. `background` peut être omis et accepte seulement `auto`. Une requête SVG renvoie HTTP `400`, pas un PNG.

### PNG avec attente synchrone

```bash
curl https://apiany.ai/v1/images/generations/sync \
  -H "Authorization: Bearer $APIANY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-image-2.6","prompt":"A polished studio photograph of an orange ceramic robot","output_format":"png","size":"1:1","n":1}'
```

### GIF avec une image de référence

L’endpoint d’édition accepte un JSON contenant une entrée `image_urls` ou un fichier multipart `image`. N’ajoutez pas de masque. `output_format` choisit le format de sortie ; l’édition GIF renvoie également un seul fichier animé.

```bash
curl https://apiany.ai/v1/images/edits \
  -H "Authorization: Bearer $APIANY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-image-2.6","prompt":"A friendly orange robot waving in a smooth loop","output_format":"gif","size":"1:1","n":1,"image_urls":["https://example.com/reference.png"]}'
```

Vous pouvez aussi envoyer un fichier de référence avec multipart/form-data :

```bash
curl https://apiany.ai/v1/images/edits \
  -H "Authorization: Bearer $APIANY_API_KEY" \
  -F "model=gpt-image-2.6" \
  -F "prompt=Animate the character waving in a smooth loop" \
  -F "image=@reference.png" \
  -F "output_format=gif" \
  -F "size=1:1" \
  -F "n=1"
```

Les endpoints synchrones et d’édition renvoient HTTP `200` avec `data[0].url` une fois terminés, ou HTTP `202` avec `task_id` et `poll_url` en attente. Interrogez `/v1/tasks/{task_id}` jusqu’à `completed` ou `failed` et gardez le même ID pour `pending` ou `processing`. La génération asynchrone utilise `/v1/images/generations` et le fichier terminé se trouve dans `result.data[0].url`. Les résultats GIF invalides ou statiques échouent et suivent la politique normale de remboursement des crédits pour les tâches échouées.
