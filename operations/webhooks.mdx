---
title: Webhooks
description: Receive async task completion callbacks.
---

Async media tasks can include a callback URL when enabled for the API key or request.

Callbacks are retried by the platform when delivery fails.

The JSON callback includes the task and request IDs, state, model, result, error
and credits. Image results carry `result.data[0].url`; video and audio results
carry `result.video_url` or `result.audio_url` and `result.urls[]`.
The `X-ApiAny-Task-Id` and `X-ApiAny-Request-Id` headers repeat the identifiers.

```json
{
  "task_id": "task_123",
  "status": "completed",
  "model": "seedance-2.0",
  "type": "video",
  "result": {
    "status": "completed",
    "video_url": "https://.../video.mp4",
    "urls": ["https://.../video.mp4"]
  }
}
```

## Verify a notification

1. Match the task ID against a job you submitted and acknowledge delivery with a `2xx`.
2. Fetch [task status](/reference/tasks) using your API key. Use the authenticated result before making downstream changes. The callback headers are correlation identifiers, not signatures.
3. Deduplicate task processing by `task_id` so repeated delivery does not trigger duplicate work.

Set `callback_url` to a public HTTPS endpoint that accepts `POST` directly.
Return `2xx` once you accept the notification. Follow [error handling](/operations/errors)
to recover a task without relying on webhook delivery.
