카탈로그에는 계정 작업 61개와 `get_capabilities`가 있습니다. 허용된 도구만 표시되며 호출마다 권한과 소유권을 다시 확인합니다. [빠른 시작](/ko/mcp-guide)을 먼저 읽으세요.

`get_capabilities`를 제외한 필드는 `arguments.input` 안에 넣습니다. 쓰기에는 공백 없는 인쇄 가능 ASCII 1~191자의 `arguments.idempotencyKey`도 필요합니다. 기본값이 있는 필드는 생략할 수 있습니다. `page_size`와 `pageSize`를 혼용하지 마세요. 연결의 `tools/list` 스키마를 따르세요.

성공 결과는 `structuredContent`와 `content`의 JSON 텍스트로 반환됩니다. 최초 실행 형식은 아래와 같습니다. 재호출은 `replayed: true`와 식별자가 있는 작은 `receipt`를 반환하며 원본 전체 결과나 키 비밀 값은 반환하지 않습니다.

```json
{
  "execution_id": "EXECUTION_ID",
  "replayed": false,
  "status": "completed",
  "data": {
    "balance": 100,
    "key": null
  }
}
```

`execution_pending`(409)은 최초 호출이 미해결임을 뜻합니다. `execution_unknown`(409) 또는 `status: unknown`은 실제 작업이 이미 발생했을 수 있다는 뜻입니다. `get_execution` 다음에 관련 작업, 주문 또는 계정 작업을 확인하세요. **새 키로 이 상태를 우회하지 마세요.** MCP 실행이 완료돼도 모델 작업이나 웹 확인은 대기 상태일 수 있습니다.

모델 결과 수집 한도는 **8 MiB 및 300초**입니다. 수집이 중단되거나 한도를 초과하면 실행 영수증에 알려진 `request_id`가 보존됩니다. 먼저 `get_execution`과 기존 요청 또는 작업을 확인하세요. 미해결 호출을 대신해 새 유료 요청을 만들거나 새 멱등 키를 사용하지 마세요. 클라이언트 연결 종료가 이미 접수된 모델 작업의 취소를 뜻하지는 않습니다.

## `get_capabilities`

읽기 · `arguments: {}`

연결 초기화 후 `{}`로 `get_capabilities`를 호출하고 `tools/list`를 확인합니다. `audience: user`, `ownership: self`, 허용된 `scopes` 및 도구, `oauth: false`가 반환됩니다. 다른 개인 도구는 업무 매개변수가 없어도 `input` 객체를 사용합니다.
