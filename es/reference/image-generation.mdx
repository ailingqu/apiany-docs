---
title: Generación de imágenes
description: Genera imágenes de forma asíncrona o con compatibilidad de espera síncrona.
---

Usa `/v1/images/generations` para la generación de imágenes en producción.

```bash
curl https://apiany.ai/v1/images/generations \
  -H "Authorization: Bearer $APIANY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "nano-banana",
    "prompt": "A bright API dashboard rendered as a product hero image",
    "size": "1k"
  }'
```

La respuesta devuelve una tarea:

```json
{
  "task_id": "task_123",
  "status": "processing",
  "poll_url": "/v1/tasks/task_123"
}
```

## Variante síncrona

`/v1/images/generations/sync` crea una tarea y espera hasta el tiempo máximo de espera configurado.

Úsala para compatibilidad y demos. Usa el endpoint asíncrono para cargas de trabajo de producción.

## Edición de imágenes

`/v1/images/edits` admite flujos de edición de imágenes estilo OpenAI cuando el modelo seleccionado admite imágenes de referencia.

## Calidad y enrutamiento de GPT Image 2.5

`gpt-image-2.5` es un alias fijo de Flare; usa `gpt-image-2.5-sunburst` para edición precisa. `quality` (`auto/low/medium/high/xhigh/max`) y `resolution` (`1K/2K/4K`) son independientes. Los píxeles explícitos deben coincidir con la resolución y APIAny elige solo rutas compatibles ordenadas por coste sin eliminar campos.

```json
{"model":"gpt-image-2.5-flare","prompt":"Imagen principal de producto","size":"16:9","resolution":"2K","quality":"high","n":1}
```

La edición admite hasta 16 referencias y una máscara opcional.

```json
{"model":"gpt-image-2.5-sunburst","prompt":"Cambiar solo el fondo","image_urls":["https://example.com/product.png"],"mask_url":"https://example.com/mask.png","resolution":"2K","quality":"xhigh"}
```

## GPT Image 2.6

`gpt-image-2.6` usa los endpoints de imagen existentes para PNG y GIF animados; no hay una API GIF separada. Cada solicitud correcta cuesta **30 créditos** y devuelve un resultado. Compruebe la disponibilidad en `GET /v1/models` antes de llamar.

Use `output_format: "png"` (predeterminado) o `"gif"`, `quality: "auto"`, `resolution: "1K"` y `n: 1`. `size` admite `auto`, `1:1`, `3:2`, `2:3`, `1024x1024`, `1536x1024` o `1024x1536`. Se acepta como máximo una referencia. Los mismos límites se aplican a alias y `model_params`; los valores contradictorios devuelven HTTP `400`.

No se admiten SVG, JPEG, WebP, 2K/4K, máscaras, compresión, `frame_count` ni `frame_duration_ms`. Las dimensiones, los fotogramas y los intervalos del GIF no se pueden configurar. `background` puede omitirse y solo admite `auto`. Las solicitudes SVG devuelven HTTP `400`, no un PNG.

### PNG con espera síncrona

```bash
curl https://apiany.ai/v1/images/generations/sync \
  -H "Authorization: Bearer $APIANY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-image-2.6","prompt":"A polished studio photograph of an orange ceramic robot","output_format":"png","size":"1:1","n":1}'
```

### GIF con una imagen de referencia

El endpoint de edición acepta JSON con una entrada `image_urls` o un archivo multipart `image`. No añada una máscara. `output_format` selecciona el formato de salida; la edición GIF también devuelve un único archivo animado.

```bash
curl https://apiany.ai/v1/images/edits \
  -H "Authorization: Bearer $APIANY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-image-2.6","prompt":"A friendly orange robot waving in a smooth loop","output_format":"gif","size":"1:1","n":1,"image_urls":["https://example.com/reference.png"]}'
```

También puede subir un archivo de referencia con multipart/form-data:

```bash
curl https://apiany.ai/v1/images/edits \
  -H "Authorization: Bearer $APIANY_API_KEY" \
  -F "model=gpt-image-2.6" \
  -F "prompt=Animate the character waving in a smooth loop" \
  -F "image=@reference.png" \
  -F "output_format=gif" \
  -F "size=1:1" \
  -F "n=1"
```

Los endpoints síncronos y de edición devuelven HTTP `200` con `data[0].url` al completarse, o HTTP `202` con `task_id` y `poll_url` mientras siguen pendientes. Consulte `/v1/tasks/{task_id}` hasta `completed` o `failed`, manteniendo el mismo ID en `pending` o `processing`. La generación asíncrona usa `/v1/images/generations` y el archivo completado está en `result.data[0].url`. Los resultados GIF no válidos o estáticos fallan y siguen la política normal de reembolso de créditos para tareas fallidas.
